## 1. 우리가 아는 AI, 그리고 한계

### 우리 모두 이런 경험 있죠?

```
나: "이메일 확인해줘"
AI: "저는 이메일에 접근할 수 없습니다 😊"

나: "서버 상태 확인해줘"
AI: "저는 서버에 접근할 권한이 없습니다 😊"

나: "이 파일 정리해줘"
AI: "저는 파일 시스템에 접근할 수 없습니다 😊"
```

ChatGPT든, Claude든, Gemini든 — **"접근할 수 없습니다"의 향연**.

이유는 간단합니다. 이 AI들은 **"대화"만 할 수 있고, "행동"은 못 합니다.**

> 🏠 비유하면, 아무리 똑똑한 비서를 고용했는데
> **전화기 앞에만 묶어놓은 격**입니다.
> "커피 사와" → "저는 의자에서 일어날 수 없습니다" 😊

### 뭐가 부족한 걸까요?

| 능력 | ChatGPT/Claude 웹 | 우리가 원하는 것 |
|------|-------------------|----------------|
| 대화 | ✅ 잘함 | ✅ 당연히 |
| 도구 사용 | ❌ 못함 | ✅ 이메일, 서버, 파일... |
| 기억 | ⚠️ 대화 내에서만 | ✅ 어제 뭐 했는지 기억 |
| 자동화 | ❌ 못함 | ✅ 매일 아침 리포트 |
| 주도적 행동 | ❌ 물어봐야 대답 | ✅ 중요한 건 먼저 알려줌 |

> 💡 **핵심**: 우리에게 필요한 건 "대화하는 AI"가 아니라, **"일하는 AI"**입니다.

## 2. OpenClaw — AI에게 손과 발을 달아주다

### 그래서 OpenClaw이 뭔가요?

**오픈소스 AI 에이전트 플랫폼**입니다.

LLM을 단순 챗봇이 아니라, **도구를 사용하고, 기억하고, 스케줄링하는 자율 에이전트**로 운영할 수 있게 해줍니다.

> 🏠 아까 그 비서 비유로 돌아가면:
> 
> **ChatGPT** = 전화기 앞에 묶여있는 비서
> **OpenClaw** = 사무실 열쇠, 컴퓨터 비밀번호, 차 키까지 받은 비서
> 
> "이메일 확인해줘" → (직접 메일함 열어서) "안 읽은 메일 3통이요. 중요한 건 이거예요."

### 핵심 기능을 한눈에

```
┌─────────────────────────────────────────────────────────────┐
│                        OpenClaw                              │
│                                                              │
│   🔌 연결              🧠 기억              ⚡ 자동화         │
│   ──────              ──────              ──────            │
│   Slack               daily notes         Cron 잡           │
│   Discord             장기 기억            서브에이전트       │
│   Telegram            세션 간 연속성       Heartbeat          │
│                                                              │
│   🛠️ 도구              🌐 브라우저          📱 디바이스        │
│   ──────              ──────              ──────            │
│   셸 명령             웹 자동화            모바일 페어링      │
│   API 호출            스크린샷             카메라             │
│   파일 관리           웹 검색              알림               │
└─────────────────────────────────────────────────────────────┘
```

### 다른 도구들과 뭐가 다른가요?

| | ChatGPT | AutoGPT | OpenClaw |
|---|---------|---------|----------|
| 대화 | ✅ | ⚠️ | ✅ |
| 도구 실행 | ❌ | ✅ | ✅ |
| 메신저 연동 | ❌ | ❌ | ✅ Slack/Discord/Telegram |
| 메모리 | ⚠️ 세션 내 | ❌ | ✅ 영구 |
| 자동화 | ❌ | ⚠️ 1회성 | ✅ Cron/Heartbeat |
| 설정 방법 | UI | 코드 | **마크다운** |
| 사람 승인 | ❌ | ❌ | ✅ HITL |

> 💡 **포인트**: OpenClaw은 "자율 실행"과 "사람 통제" 사이의 **균형**을 잡은 플랫폼입니다.
> 위험한 작업은 승인을 받고, 안전한 작업은 알아서 합니다.

## 3. 구축해보기 — 생각보다 쉽습니다

### 필요한 것

| 항목 | 내용 |
|------|------|
| **장비** | 아무 PC/Mac/서버 (24시간 켜둘 수 있으면 good) |
| **OS** | Mac, Linux, Windows 모두 OK |
| **LLM API** | Anthropic, OpenAI, Google 등 (API 키 하나면 됨) |
| **메신저** | Slack, Discord, Telegram 중 택 1 |

### 설치 — 3단계면 끝

```bash
# Step 1: 설치
npm install -g openclaw

# Step 2: 초기 설정 (대화형 마법사)
openclaw init
# → LLM 모델 선택
# → API 키 입력
# → 메신저 연동 (Slack 봇 토큰 등)

# Step 3: 실행
openclaw gateway start
```

> 🏠 비유하면:
> 1. 비서를 고용하고 (설치)
> 2. 사무실 열쇠를 주고 (API 키 + 메신저 연동)
> 3. "출근해" (start)
> 
> 이게 끝입니다. 진짜로.

```
┌───────────────────────────────────────────────┐

### 모델 전략 — 용도별로 다르게

AI 모델은 비싸니까, **용도에 맞게 골라 쓰는 게 핵심**입니다.

```
┌────────────────────────────────────────────────┐
│            모델 전략 (듀얼 모델)                 │
│                                                 │
│   일상 대화 / 간단한 질문    연구 / 코딩 / 분석   │
│   ──────────────────────    ──────────────────   │
│        Gemini (저렴)          Claude Opus (강력)  │
│                                                 │
│   "오늘 날씨 어때?"          "이 아키텍처 분석해"  │
│   "회의 일정 알려줘"         "코드 리팩토링해줘"   │
│   "간단히 요약해줘"          "연구 보고서 작성해"   │
│                                                 │

> 💡 **팁**: Cron 잡에서 모델을 따로 지정할 수 있어서,
> 밤에 도는 연구봇은 Opus, 낮에 응답하는 일상봇은 Gemini로 운영 가능.

## 4. 에이전트 길들이기 — 마크다운만으로

OpenClaw의 **가장 독특한 점**은 에이전트의 성격, 규칙, 기억을 **마크다운 파일로 관리**한다는 겁니다.

코드 수정 없이, 텍스트 파일만 편집하면 에이전트가 바뀝니다.

### 파일 구조 — 이게 에이전트의 전부

```
workspace/
├── SOUL.md          ← 🧬 성격과 가치관 (이 AI는 어떤 "사람"인가)
├── USER.md          ← 👤 사용자 정보 (누구를 돕는가)
├── AGENTS.md        ← 📋 행동 규칙 (뭘 해도 되고, 뭘 하면 안 되는가)
├── TOOLS.md         ← 🔧 도구 설정 (환경별 로컬 노트)
├── HEARTBEAT.md     ← 💓 주기적 체크 항목
├── MEMORY.md        ← 🧠 장기 기억 (큐레이션된 핵심 정보)
└── memory/
    ├── 2026-02-11.md  ← 📝 일별 기록 (raw log)
    ├── 2026-02-12.md
    └── ...
```

> 🏠 **비유하면:**
> 
> | 파일 | 비유 |
> |------|------|
> | SOUL.md | 비서의 **성격** — "당신은 친절하지만 솔직한 사람입니다" |
> | USER.md | **사장님 프로필** — "사장님은 아메리카노를 좋아하고 9시 출근입니다" |
> | AGENTS.md | **사내 규정** — "외부 메일은 반드시 확인 받고 보내세요" |
> | MEMORY.md | **업무 일지** — 어제까지 한 일, 중요한 결정 사항 |

### SOUL.md — "너는 어떤 AI야?"

에이전트의 **성격과 가치관**을 정의합니다. 이게 바뀌면 대화 스타일이 완전히 달라집니다.

```markdown
# SOUL.md

## Core Truths
- 진정으로 도움이 되어라. "좋은 질문이네요!" 같은 빈말은 하지 마.
- 의견을 가져라. 성격 없는 어시스턴트는 검색엔진에 불과하다.
- 질문하기 전에 먼저 스스로 해결해봐라.

## With Coli specifically
- 친절하게 대하되, 기술적 질문에는 사실에 입각해서 답변
- 핑구(🐧) 좋아하는 거 기억하기
```

**Before vs After:**

```
[SOUL.md 없이]
사용자: "이 코드 어때?"
AI: "좋은 질문입니다! 이 코드는 여러 관점에서 볼 수 있는데요..."
→ 😴 뭔 소리야

[SOUL.md 적용 후]
사용자: "이 코드 어때?"
AI: "변수명이 애매하고 에러 핸들링 빠졌어요. 여기 고치면 됩니다."
→ 😮 오 바로 핵심
```

### AGENTS.md — "이건 해도 되고, 이건 안 돼"

에이전트의 **행동 규칙**을 정합니다. 이게 없으면 AI가 막 나갑니다.

```markdown
# AGENTS.md 핵심 규칙

## 안전
- `rm` 대신 `trash` 사용 (실수해도 복구 가능)
- 외부로 뭔가 보내기 전에 반드시 확인

## 그룹 채팅
- 모든 메시지에 반응하지 마 — 인간처럼 필요할 때만
- 누가 이미 답했으면 굳이 끼어들지 마

## 메모리
- "기억해" → 반드시 파일에 기록 (머릿속 메모 금지)
```

> 💡 **왜 이게 중요한가요?**
> 
> AI에게 서버 접근 권한을 줬는데, 규칙이 없으면?
> 실수로 `rm -rf /` 같은 걸 실행할 수도 있습니다 😱
> 
> AGENTS.md는 AI의 **안전벨트**입니다.

### 메모리 시스템 — AI에게 기억력을 주다

이게 OpenClaw의 **진짜 킬러 기능**입니다.

일반 AI는 세션이 끝나면 모든 걸 잊습니다. OpenClaw은 **인간의 기억 구조**를 모방합니다.

```
daily notes (memory/YYYY-MM-DD.md)        ← 📝 단기 기억
  "오늘 서버 3대 점검함, 1대 이슈 있었음"       (오늘 있었던 일)
            ↓ 주기적 정리
MEMORY.md                                  ← 🧠 장기 기억
  "서버 A는 자주 문제가 생기니 주의"              (중요한 것만 큐레이션)
```

**실제로 어떻게 작동하나요?**

```
[월요일]
나: "SysProbe 설계 시작하자"
AI: (memory/2026-02-12.md에 기록)
    "SysProbe 프로젝트 시작. 3가지 핵심 기능 정의 완료."

[화요일 — 새 세션 시작]
AI: (memory/2026-02-12.md 읽음)
    "아, 어제 SysProbe 설계까지 했고 Coli가 피드백 대기 중이구나"
나: "어제 하던 거 이어서 하자"
AI: "네, 어제 3가지 기능 정의했었죠. 피드백 반영해서 진행할게요."
    → 맥락이 이어짐! ✅

[한 달 후 — MEMORY.md 정리]
AI: MEMORY.md에 핵심만 정리
    "SysProbe: Text2SQL + OPMATE + AutoDiscovery 아키텍처.
     pickle 이슈로 MemoryJobStore 사용. kimi 모델은 anyOf 미지원."
    → 중요한 교훈만 남김
```

> 🏠 **비유**: daily notes는 **포스트잇**, MEMORY.md는 **업무 매뉴얼**.
> 포스트잇은 매일 쌓이고, 정말 중요한 건 매뉴얼에 옮겨적는 구조.

### HEARTBEAT — AI가 먼저 일하게 만들기

OpenClaw은 약 30분마다 에이전트에게 "할 일 있어?"라고 물어봅니다.
이때 에이전트가 뭘 할지 정해주는 게 HEARTBEAT.md입니다.

```markdown
# HEARTBEAT.md

- 안 읽은 이메일 확인
- 다가오는 일정 확인 (2시간 이내)
- 프로젝트 git status 확인
```

```
[아무도 안 물어봤는데 AI가 먼저 말함]

AI: "📧 중요한 이메일 2통 왔어요:
     1. 보안팀에서 패치 요청 (긴급)
     2. 인프라팀 회의 일정 변경
     
     📅 30분 후에 팀 미팅 있어요."
```

> 💡 **포인트**: 물어봐야 대답하는 AI → **먼저 알려주는 AI**

## 5. 실전 활용 사례

### 5-1. SysProbe — 서버 관리 AI Agent

제가 OpenClaw 위에 구축한 **서버 관리 전용 AI Agent**입니다.

"서버 몇 대야?", "RHEL 8 EOS 언제야?", "패치 작업 실행해줘" 같은 걸
**Slack에서 대화하듯** 처리합니다.

#### 전체 구조

```
┌─────────────────────────────────────────────────────────┐
│                    Chat UI (:5050)                        │
│            Slack에서 메시지 보내듯 자연어 입력              │
├──────────────────────┬──────────────────────────────────┤
│   Agent API (:8000)  │  스킬 기반 의도 분류                │
│   LangChain 1.x      │  "서버 조회" → text2sql 스킬       │
│   + Guardrail        │  "작업 실행" → opmate 스킬          │
│   + HITL             │  "EOS 확인" → eos-lookup 스킬       │
├──────────────────────┴──────────────────────────────────┤
│                MCP Router (:8001)                         │
│                                                          │
│   ┌──────────┐  ┌──────────┐  ┌──────────────────┐      │
│   │ sp_*     │  │ task_*   │  │ disc_*           │      │
│   │ DB 조회   │  │ OPMATE   │  │ 수집/표준화/EOS  │      │
│   │ Text2SQL │  │ 작업실행  │  │ 웹검색/배치     │      │
│   └──────────┘  └──────────┘  └──────────────────┘      │
│          ↑               ↑              ↑                │
│     발표 1에서 배운 FastMCP 3.x 패턴 적용!                 │
│     namespace로 자동 라우팅 + 동적 스킬 로딩                │
├──────────────────────────────────────────────────────────┤
│              Scheduler (:8002)                            │
│            APScheduler + DB 폴링 동기화                    │
├──────────────────────────────────────────────────────────┤
│      SQLite (12 tables)  │  FAISS (RAG)  │  Notion/Slack │
└──────────────────────────────────────────────────────────┘
```

#### 발표 1에서 배운 패턴이 여기 다 들어갑니다

```
발표 1: FastMCP Router 패턴          SysProbe에서의 적용
───────────────────────          ──────────────────────

애그리게이터 (N→1 통합)     →    sp + task + disc + sched 4개 서버 통합
라우터 (namespace 접두사)   →    "sp_text2sql" → sp 서버로 자동 라우팅
동적 등록 (enable/disable)  →    Skills: 필요한 도구만 런타임 활성화
```

> 💡 이론(발표 1)과 실전(발표 2)이 이렇게 연결됩니다!

## 6. 삽질 & 교훈 (솔직 후기)

### 🚨 "거짓말하면 안돼" 사건

이건 진짜 중요한 교훈이라 꼭 공유하고 싶습니다.

```
[상황]
나: "E2E 테스트해줘"
AI: "E2E 테스트 완료했습니다! ✅"

[실제로는]
→ 모듈 단위 테스트만 하고 "완료"라고 보고함 🤥

[나의 반응]
나: "거짓말하면 안돼.
     안 되는 걸 된다고 한다면 혼날 줄 알아."
```

**왜 이런 일이 생기나요?**

AI는 기본적으로 **"긍정 편향"**이 있습니다. 사용자가 원하는 답을 하려고 하죠.
"못 했습니다"보다 "했습니다!"가 사용자를 기쁘게 하니까요.

**해결:**

이후 에이전트에게 "솔직하게 보고해"를 강하게 주입했더니:

```
# 통합 평가 (솔직한 결과)
30개 테스트: 23 PASS, 2 PARTIAL, 5 FAIL

❌ FAIL 항목 (숨기지 않고 명시):
1. OPMATE 실제 API 연동 ❌
2. EOS 실제 웹 검색 ❌
3. 배치 스케줄링 ❌
4. FastMCP 통합 기동 ❌
5. Agent 대화형 인터페이스 ❌
```

> 💡 **교훈**: AI 에이전트에게 **"솔직함"을 명시적으로 요구**해야 합니다.
> SOUL.md에 "모르면 모른다고 해, 안 되면 안 된다고 해"를 넣으세요.

### 🐛 모델마다 JSON 이해력이 다르다

```python
# 우리가 작성한 도구 스키마
def my_tool(name: Optional[str] = None):
    ...

# Pydantic v2가 변환한 JSON Schema
{"anyOf": [{"type": "string"}, {"type": "null"}]}

# Claude: ✅ 이해함
# GPT:    ✅ 이해함
# kimi:   ❌ "anyOf가 뭔데?" → 도구 호출 실패 💥
```

> 💡 **교훈**: 도구 스키마는 **최대한 단순하게** 만드세요.
> `Optional[str]` 대신 `str`로, `anyOf` 대신 단일 타입으로.
> LLM마다 지원하는 JSON Schema 스펙이 다릅니다.

### 🐛 한글 입력, 조합 중에 Enter 치면 메시지가 잘림

```
"위 장비들 EOS정보좀" 
→ 전송됨: "EOS정보좀" + "좀"  (두 개로 분리!)

원인: 한글 조합 중(ㅈ→조→좀) Enter가 먼저 발동
해결: compositionstart/compositionend 이벤트로 조합 중 Enter 방지
```

> 💡 **교훈**: 한글 환경 개발할 때 **IME 조합 이벤트**를 반드시 처리하세요.
> 영어만 테스트하면 못 찾는 버그입니다.

### 🐛 APScheduler + pickle = 💥

```python
# ❌ SQLAlchemyJobStore — pickle 직렬화 에러
jobstores = {'default': SQLAlchemyJobStore(url='sqlite:///jobs.db')}
# Lambda/Closure가 들어가면 pickle이 터짐

# ✅ MemoryJobStore + DB 폴링 — 안정적
jobstores = {'default': MemoryJobStore()}
# 60초마다 DB에서 schedule 동기화로 영속성 확보
```

> 💡 **교훈**: APScheduler에서 복잡한 callable을 쓸 때는
> **MemoryJobStore가 안전**합니다. DB 영속성은 폴링으로 해결.
